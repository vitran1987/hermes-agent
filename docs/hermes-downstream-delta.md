# Hermes downstream delta

The ledger of every change **we** carry against upstream Hermes (community repo
`NousResearch/hermes-agent`, our fork `vitran1987/hermes-agent`).

Policy: `.github/PROCESS-KEY-PRINCIPLES.md` §20 and
`.github/skills/shared/hermes-core-immutable/SKILL.md`.
CEO directive 2026-11-18 (kanban `t_eb00e103`): *core is append-only through
reviewed commits* — `hermes update` still runs `git reset --hard` in the live
install, so a change that is not a commit on a fork branch is gone on the next
update, with no record of what it did.

## The rule, in one paragraph

A core change is allowed when **all four** hold: (1) it is a commit on a branch
in `vitran1987/hermes-agent`; (2) it has a test or a reproduction command that
failed before and passes after; (3) `code-reviewer-bangioi` approved the PR that
carries it; (4) it has a row in **this** file naming the file and the reason.
Nothing else is required — there is no approval marker to paste into a PR body.
